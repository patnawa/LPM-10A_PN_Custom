# Firmware audit — 2026-09-19

Scope: TX patch composition, binary allocation, battery shutdown, and the existing
PoE/FLASH and screen verification. This is a targeted source and emulation audit,
not a proof of all vendor code or a hardware test. The stock image was available
locally and matched the pinned SHA-256. The existing PN 2.4 verifier passed before
changes. PN 2.4 remains the hardware-tested release; PN 2.5 is a local candidate.

## Confirmed and fixed

| Severity | Finding and reproduction | Fix |
|---|---|---|
| High | Battery debounce survives cancellation. Three low readings arm shutdown; recovery to 3300 mV or connecting a charger cancels it; the next low reading immediately returns `arm=1`. The UI skips the low-sample hook while shutdown is active or a charger is connected, so those paths cannot clear its counter. | `p_batt_debounce` clears the counter when the cancellation hook returns true. Emulation now returns `[0, 0, 1]` for the next three low samples after either cancellation path. The 3150/3250 mV thresholds and 30 s grace remain the same. |
| High (tooling) | `Image.emit_code` sizes code at `cave_start`, then emits at the current allocation address. An alignment directive can increase the real size; the allocator reserves too few bytes, allowing the next block to overwrite it. A synthetic image with `.word 1`, then `.align 16; .word 0x12345678`, reproduces the underrun. | Assemble at the actual aligned allocation address and reserve that exact size. The regression appends another block and verifies the preceding bytes remain intact. No evidence that the shipped PN 2.4 blocks hit this case. |
| High (custom builds) | Calibration and blind-pair text can be applied without `length-decimal`. Calibration controls then change settings that stock conversion ignores; the decimal formatter can divide stock integer values by ten while retaining stock unit labels. Thai unit wording also assumes the changed unit order, and its font patch requires `font-pro`. | Declare dependencies and enforce them before a patch mutates the image. The CLI rejects incomplete selections before loading stock and lists prerequisites in `--list`. Direct SDK callers get the same guard. |
| Medium | `--only length-decimal,length-average` fails even though its dependency is present: averaging checks a hard-coded branch encoding whose target assumes `autooff-hold` consumed the first cave bytes. | Compare with the branch to the actual recorded conversion address. Test both with and without the earlier patch. The blind formatter likewise checks its actual predecessor target. |
| Medium (tooling) | The TX parser accepts a header whose payload extends beyond EOF; reads can reach header bytes or silently truncate; invalid allocation sizes/alignment can move pointers backwards; unterminated strings raise an incidental `IndexError`. | Validate header/payload bounds, complete read/write ranges, allocations and owned regions; reject unterminated strings with `PatchError`. |
| Low (CLI) | `--only` silently ignores `--with`/`--all`, and an empty `--only` unexpectedly selects the defaults. | Reject conflicting or empty selections. |

The new `sdk/test_audit.py` suite contains synthetic-image tests that need no vendor
file, plus patch and CPU-emulation tests that use the locally supplied stock image.
The latter are explicitly skipped when stock is unavailable. Every registered patch
is also constructed with its declared dependencies; this checks composition, not
hardware behavior of experimental patches.

## Remaining risks and follow-up

- **Interrupt/RTOS calls:** the existing audit records task-level queue calls from
  interrupt context and a watchdog fed from TIM2. A hung task may therefore survive
  indefinitely. Repairing this needs a scheduling design and hardware soak tests;
  the battery fix does not address it.
- **Battery startup and sampling gaps:** the debounce counter still lives in
  uninitialised RAM, and stock skips UI sampling while a test runs or charging.
  The new fix guarantees fresh samples after cancellation of an active shutdown;
  it does not establish uninterrupted sampling across every charging/test/startup
  transition. Startup initialisation and a single sampling owner are follow-up work.
- **PoE concurrency review:** `poe_tick` and `live_check` share a partial-redraw byte,
  rather than carrying redraw type in each queued message. `latch_hook` copies the
  sample block with multiple loads and stores. Existing tests cover an update after
  the latch is copied, but not preemption during the copy or all queue interleavings.
  These are coverage gaps and possible races, not hardware-reproduced failures.
- **PoE classification:** the vendor byte-spread comparison against 40000 remains
  ineffective. Changing that threshold without recovering the intended behavior
  could alter working classification. Test with real standard and passive supplies.
- **Receiver:** the available patched RX image is based on V3.0.0; the reported probe
  runs V3.0.1. No receiver image was changed or flashed in this audit.

## Candidate and validation

`LPM-10A/Firmware File/LPM-10A-TX_PN2.5.bin` is 393216 bytes, with SHA-256:

```
ae3bb28dbdbefa03878bbe12f508b0b147ef10f1fee98870f72c41327fb2c1cf
```

The runtime change is the battery-cancellation reset, plus version identification.
Later cave blocks move by 12 bytes, so a full build verification is required even
though their behavior is unchanged. The original PN 2.4 binary is retained.

Validation completed: all 12 audit regression tests passed, the assembler
self-test passed, and the full `verify.py` run passed on PN 2.5. This includes
all 61 screen states in Thai against the design model and all 61 in English
against the corresponding build without Thai, plus PoE and FLASH emulation.
The valid two-patch averaging dry run also passed; a blind-text-only selection
was rejected with its missing dependency identified. `git diff --check` passed.

Run from `LPM-10A/Firmware File/sdk`:

```
python -m unittest test_audit -v
python test_thumb.py
python build.py --write
python verify.py
```

Hardware acceptance still needed: battery recovery and charger cancellation followed
by another low-voltage episode, normal boot/settings/length behavior, FLASH operation,
and PoE with a supply. No device was flashed during this audit.
