# TX PN2.33 — LAN cable colours, keys ignored while testing, stricter RX unit mode

The owner tested PN2.33 on the tester and reported on 2026-09-24:

> 2.33 test pass

This release publishes that exact TX image. RX PN1.29 remains the current
receiver firmware; no RX change is needed.

It follows an audit of the Cable Test on PN2.27A (real firmware in the
emulator, 29 findings, [report](https://github.com/patnawa/LPM-10A_PN_Custom/blob/v2.33/docs/TX-CABLE-TEST-AUDIT-2026-09-23.md))
and four device rounds on 2026-09-24 (PN2.28 → 2.33).

- **Wires in their LAN cable colours (T568B).** 1 white-orange, 2 orange,
  3 white-green, 4 blue, 5 white-blue, 6 green, 7 white-brown, 8 brown,
  G silver. The white-striped wires carry white dashes, along crossed
  diagonals too. The reading at the end of each wire is in the wire's colour.
  Fault colours win: red = open (with the X), yellow = short.
- **Keys during the test** (about 0.86 s). OK is ignored, so extra presses no
  longer queue more tests; Back during a test leaves no stray "Test Retry"
  button and the next screen says "Test Start"; a test queued before leaving
  the screen can no longer paint the Cable Test layout over Home or SPEED;
  the button reads **Testing…** / กำลังทดสอบ while measuring.
- **RX unit mode.** Each wire goes to the nearest ladder value of the median
  of its non-floating readings, with a common gain estimate over all wires
  (±7 %), instead of stock's "any one of eight readings inside the driven
  pin's own ±5 % window" (the windows overlap from pin 5 up, so a 6↔7 or
  8↔G swap could pass as straight). Results no RX unit can produce — two
  wires on one remote pin, a wire on an open shield, one level on every wire
  (a leaking, unplugged cable) — show **Result error!!** with a red LED
  instead of a made-up wire map. The short and open rules are unchanged.
- **Switch mode** decides exactly as PN2.27A did, in the new colours.
  A pair-partner check (wrong pair = red, short between pairs = yellow) was
  tried in PN2.28–2.30 and withdrawn: on the owner's switch the port's
  centre-tap paths between pairs read within a few counts of the pair
  winding, and every wire of a good cable went yellow. Bringing it back
  needs readings from the diagnostic build `LPM-10A-TX_PN2.30D-diag.bin`
  (two lowest readings per wire) on a good cable in the switch.
- **Unchanged:** thresholds 1240 / 4000, the RX ladder, eleven samples per
  pin, the PN2.19 open rule, Length, SPEED, FLASH, PoE, SCAN tone, QC.
  The file is still **401,408 bytes**.

Validation: 56 Cable Test tests run the real routines under Unicorn against
modelled far ends (switch pairs, centre-tap paths, a 4-5-7-8-tied 10/100 port,
miswires, shorts, the RX ladder at −5 % … +5 % gain with 50 Hz hum, leakage);
each defect test also runs the parent build and asserts its wrong answer. The
full TX run completed 551 tests (one optional preview-image test skipped). An independent code review of PN2.28 found the
Switch-mode centre-tap false short (later confirmed on the device) and an
RX-unit averaging weakness, both addressed. All figures are emulator results;
the device confirmation is the owner's report.

**Install `LPM-10A-TX_PN2.33-cable-safe.bin` on the TX tester.** Power off,
hold **M + Power** to enter update mode, connect USB-C, copy the file onto the
removable drive, wait for the copy to finish, power off and on. About shows
`Software:PN2.33`. If QC requests Init, disconnect every cable and hold Right.
For rollback, install the
[PN2.27A release](https://github.com/patnawa/LPM-10A_PN_Custom/releases/tag/v2.27A)
the same way.
