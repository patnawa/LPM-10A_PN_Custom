# TX PN 2.23 — the Length screen's REF target before a measurement (plus everything in v2.21)

The build running on the owner's tester (2026-09-21). PN 2.21 passed every function; the owner's first
use of its REF target met a silent skip — holding OK on the Length screen went ZERO → NVP because PN 2.18
offered REF only while a result was on screen. PN 2.22 makes REF reachable whether or not something has
been measured, and PN 2.23 fixes what PN 2.22 showed on the unit the first time (`REF 189.1`, the RAM
cell's power-up content). Confirmed on the unit the same day. The image is the exact PN 2.14 release image
plus one patch per version, so PN 2.15 … 2.22 in `experimental/` bisect a problem if one ever appears:

Install: tester off → hold **M + Power** until the update screen → plug USB-C → copy the file to the
drive → long-press Power, power on. About reads `Software:PN 2.23`. Rollback: the PN 2.21 file

same procedure, no settings change. The file is two 4 KB pages longer than stock (as PN 2.21 was); the
bootloader takes it.

## Using REF

Set **Zero** first on a short cable as before (hold OK once: ZERO white, UP / DOWN). Then either order:

- *Measure, then tell the tester the length:* plug the long cable with its far end open, press OK, wait
  for the four readings, hold OK twice → `REF 20.3` (the measured length), dial to the true length; every
  step solves NVP and redraws the readings.
- *Tell it the length, then measure:* hold OK twice → `REF 10.0`, dial to the cable's true length, press OK
  to measure; the result comes back equal to REF (within NVP's 1 % step) and the grey `NVP nn%` shows the
  solved value. Measure again: the same reading, NVP untouched.

NVP is saved on leaving the screen, as every calibration value. "Out of range" and "Test timeout!!" are
not results: a REF dialled before them stays pending until a real result arrives.

## Verification

- Every version is a profile in `sdk/profiles.py`; `sdk/test_profiles.py` rebuilds all sixteen TX images
  (baseline, PN 2.9 … 2.23) in memory and compares them with the published digests.
- `test_length_ref_anytime.py` (7) and `test_length_ref_reset.py` (8) run the real code end to end under
  Unicorn: the whole Length measurement (`APP_LENG_Test_Sequence` with a simulated PHY), the keys through
  the real `Action_key_Process`, the drawing through the real GUI task, English and Thai — the fit
  (REF 20.0 m on a 2031 cm mean → 68 %), no re-fit on the next measurement, the PN 2.18 order still solving
  at once, pending cleared on leaving REF or the screen, and PN 2.22's `REF 189.1` reproduced (18910 in the
  cell) and gone on PN 2.23. The earlier files: `test_length_progress.py` (6), `test_about_values.py` (6),
  `test_speed_partner.py` (10), `test_length_reference.py` (8), `test_cable_test.py` (10),
  `test_cable_clear.py` (4), `test_cable_values.py` (6). 269 sdk tests, `verify.py` (baseline, 235 checks)
  and the assembler self-test pass.
- Hardware: PN 2.21 on the owner's unit, 2026-09-21, every function; PN 2.22 flashed the same evening
  (REF reachable, but `REF 189.1` the first time); PN 2.23 flashed after it: REF as designed.
