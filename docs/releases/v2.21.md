# TX PN 2.21 — run counter, About values, SPEED partner row, REF calibration, a Cable Test that says "Not connected" and shows its readings

The build running on the owner's tester (2026-09-21): PN 2.19 passed every function, PN 2.20 fixed
the one thing reported (a stale "Not connected" line), PN 2.21 adds the readings on the wires the owner
asked for after seeing the diag build — all confirmed on the unit the same day. It is the exact PN 2.14
release image plus one patch per version, so PN 2.15 … 2.20 in `experimental/` bisect a problem if one
ever appears:

| Version | Patch | What it adds |
|---|---|---|
| PN 2.15 | `length-progress` | the Length screen's Testing line counts the averaging runs, `1/4 … 4/4` |
| PN 2.16 | `about-values` | About shows `BATT 3874mV  NVP 68%  ZERO 0.4m` under Factory Reset |
| PN 2.17 | `speed-partner` | SPEED gets a **Switch** row: the speeds the link partner advertises (IEEE registers 5 and 10) — a 100 Mbps link on a `10/100/1000` port points at the cable, on a `10/100` port at the port |
| PN 2.18 | `length-reference` | hold OK: NVP → ZERO → **REF**; dial the known length of the cable on screen and NVP is solved from it, `NVP = 69 × REF / (raw − 10·Zero)` |
| PN 2.19 | `cable-robust` | Cable Test reads eleven samples per sensed pin and uses the median (the highest for the far-end open test); Switch mode needs a real short (≤ 1240); all signal pins open prints **Not connected** / ไม่พบปลายสาย; the second mode is named **RX unit** / เครื่องรับ |
| PN 2.20 | `cable-text-clear` | the text line under the wires is wiped before every test: a Test Retry from the result screen never redrew it, so PN 2.19's "Not connected" (and stock's "Result error!!") could outlive the result it belonged to |
| PN 2.21 | `cable-values` | every wire ends with the reading that decided it, in the wire's colour: Switch mode `2   60` (the partner pin through the switch and the reading; `- 4037` = nothing reached — a single swapped wire shows the wrong letter where stock only draws green), RX unit mode `1655` (the ladder value = the remote pin) |

The Cable Test change fixes the random open / crossed wires the owner saw on a cable
not plugged into anything: stock took one ADC sample per pin and called a pin open only
above 4000 of 4095 (77 mV under the rail), which mains hum on a floating wire crosses at
random. No measurement (length, PoE, FLASH) changes in the seven.

Pair with **RX PN 1.23** ([rx-v1.23](https://github.com/patnawa/LPM-10A_PN_Custom/releases/tag/rx-v1.23)); no RX change is needed.

Install: tester off → hold **M + Power** until the update screen → plug USB-C → copy the file to the
drive → long-press Power, power on. About reads `Software:PN 2.21`. Rollback: the PN 2.14 file
(`experimental/LPM-10A-TX_PN2.14-tone-recovery.bin`), same procedure, no settings change.

## Verification

- Every version is a profile in `sdk/profiles.py`; `sdk/test_profiles.py` rebuilds all fourteen TX
  images (baseline, PN 2.9 … 2.21) in memory and compares them with the published digests.
- Each patch has a test file that runs the real firmware routines under Unicorn in English and
  Thai: `test_length_progress.py` (6), `test_about_values.py` (6), `test_speed_partner.py` (10),
  `test_length_reference.py` (8, the keys through the real `Action_key_Process`), `test_cable_test.py`
  (10, the wire map with simulated far ends and hum — PN 2.18 is random on the same readings,
  PN 2.19 is not), `test_cable_clear.py` (4, the owner's retry sequence: stale on PN 2.19, clean on
  PN 2.20), `test_cable_values.py` (6: straight, a swapped wire, open with hum, the RX ladder straight /
  crossed / shorted, Thai). 254 sdk tests, `verify.py` (baseline, 235 checks) and the assembler self-test
  pass.
- Hardware: PN 2.19 on the owner's unit, 2026-09-21, every function; PN 2.20 and PN 2.21 flashed the same
  day, Cable Test in both modes unplugged / in a switch / in the RX unit with retries between them. The
  owner also flashed the `cable-diag` build (397 312 bytes, two pages longer than stock): the bootloader
  takes it.

## Notes

- A Cable Test takes about 0.9 s (was 0.15 s). G (the shield) shows open on an unshielded cable
  or a switch every time — it is not counted, neither for the LED nor for the message.
- The readings: a floating wire well under 4095 (say 3800) is leakage or moisture; a switch partner
  well above 60 (say 300) a poor contact. A crossover cable reads like a straight one in Switch mode,
  as in stock (the switch joins whole pairs); RX unit mode shows its crossing lines and swapped values.
- `FORMULA-AUDIT.md` §4 was corrected on the way: `CNT_run_test` is the QC (crimp) test; the wire
  map is §4.1. §1.7 (REF) and §2 (partner registers) are new.
