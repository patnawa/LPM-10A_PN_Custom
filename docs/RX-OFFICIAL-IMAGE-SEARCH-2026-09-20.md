# RX: ผลค้นและตรวจไฟล์เฟิร์มแวร์ทางการ

ตรวจเมื่อ 2026-09-20 จาก [หน้าดาวน์โหลด FNIRSI](https://www.fnirsi.com/pages/manuals-firmwares) และแค็ตตาล็อกที่หน้านี้ใช้งาน. **พบ RX เพียงไฟล์ V3.0.0 ที่ใช้เป็นฐานของโครงการอยู่แล้ว**; ไม่พบ RX อีกเวอร์ชันในแพ็กเกจที่ตรวจ จึงยังไม่มีไฟล์ทางการอีกตัวสำหรับเทียบกับโครงสร้าง RAM ของเครื่องจริงที่แตกต่างจากฐานนี้

## ขอบเขตผลค้นและหลักฐานที่เก็บ

- แค็ตตาล็อกที่ดึงใหม่ยังแสดง 10A V2.0.7 / V2.0.3 / V1.0.1 และ 10C V1.1.2; ไม่มีชื่อรุ่น RX V3.0.1 หรือ URL ดาวน์โหลด RX เพิ่มเติมใน metadata นี้. `updateTool` และ `updateTutorial` ของสองรุ่นเป็นรายการว่าง
- หมายเลขรุ่นแพ็กเกจไม่ใช่หมายเลขรุ่น RX ภายใน: ตัวอย่าง V2.0.7 บรรจุ RX V3.0.0. ชื่อ `3.0.1.TXT` จาก UDISK ไม่ได้กลายเป็นหลักฐานรุ่นแอปจากการค้นครั้งนี้
- ผลนี้ครอบคลุมรายการทางการและ ZIP ที่ระบุเท่านั้น ไม่รับรองว่า FNIRSI ไม่เคยมี RX รุ่นอื่นหรือไม่มีไฟล์ที่เผยแพร่ผ่านช่องทางอื่น. ไม่ได้ใช้ไฟล์จากบุคคลที่สามหรือเดาชื่อ URL
- [Manifest ของแพ็กเกจ](experiments/results/rx-official-package-audit-2026-09-20.json) เก็บ source URL, ขนาด, SHA-256 และสมาชิกไฟล์ทุกไฟล์รวม release notes โดยไม่คัดลอกเนื้อหาเอกสารเต็ม
- [แค็ตตาล็อกเฉพาะสองรุ่น](experiments/results/rx-official-catalog-excerpt-2026-09-20.json) เก็บ metadata ที่ใช้เลือกแพ็กเกจ. ไม่เก็บแค็ตตาล็อกทั้งชุดหรือ binary ใน repository
- ขอบเขตการค้นงานวิจัย bypass และสิทธิ์ L1 อยู่ใน [เอกสาร SWD protection](RX-SWD-PROTECTION-REFERENCE-2026-09-20.md#ตรวจเพิ่ม-เขียนเฉพาะแอป-rom-crc-และงานวิจัยตรงรุ่น); การไม่พบวิธีตรงรุ่นในขอบเขตนั้นไม่ใช่ข้อพิสูจน์ว่าไม่มีช่องโหว่

ZIP ต้นฉบับและ manifest ระหว่างตรวจเก็บชั่วคราวนอก repository ที่ `%TEMP%\codex-fnirsi-rx-archive-audit-20260920`. งานนี้ไม่มีคำสั่งกับฮาร์ดแวร์ และไม่แก้เฟิร์มแวร์

## ตรวจต่อ: ตัวอย่าง updater จากผู้ผลิตชิป

หลังผู้ใช้ถามว่าสามารถดำเนินการต่อได้ไหม ตรวจแพ็กเกจที่เชื่อมจาก
[หน้าทรัพยากร N32L40x ของ NSING](https://nsing.com.sg/product/General/cortexm4/N32L403/)
เพิ่มอีกสองชุด โดยอ่าน source เท่านั้น ไม่มีการรันตัวอย่างหรือคำสั่งกับ RX:

| แพ็กเกจ | ผลตรวจ |
|---|---|
| [SDK V2.3.0](https://nsing.com.sg/api/dowfilebefore?did=4971) | ตัวอย่าง `USB/Mass_Stroage_DataFlash` เป็น block storage ที่อ่าน/เขียน internal flash โดยตรงผ่าน `MAL_Read` / `MAL_Write`; ไม่พบกฎยอมรับไฟล์อัปเดตของ FNIRSI ในตัวอย่างนี้ |
| [Two-level BOOT application note V1.0](https://nsing.com.sg/api/dowfilebefore?did=4985) | เอกสารและ ZIP ซ้อนเป็นตัวอย่าง IAP ผ่าน CAN ไม่ใช่บูตโหลดเดอร์ UDISK ของ RX |

การใช้ชิปตระกูลเดียวกันและ USB mass storage เหมือนกันยังไม่พิสูจน์ว่าใช้
โปรแกรมอัปเดตเดียวกัน จึงนำตัวอย่างเหล่านี้ไปแทนบูตโหลดเดอร์ RX ไม่ได้จาก
หลักฐานที่มี และคำแนะนำ format ในตัวอย่าง block storage ไม่ใช่คำแนะนำสำหรับ RX

เก็บ URL, ขนาด, SHA-256 และรายการไฟล์ที่เกี่ยวข้องไว้ใน
[manifest ของการตรวจ SDK](experiments/results/rx-sdk-updater-search-2026-09-20.json).
ZIP อยู่ที่ `%TEMP%\codex-rx-sdk-update-followup-20260920`.
การค้นเพิ่มเติมนี้ยังไม่ได้ไฟล์ RX ที่ยืนยันความเข้ากันได้หรือวิธียืนยันการติดตั้ง
PN 1.13 ขั้นที่ยังขาดคือไฟล์/ข้อกำหนด updater ที่ตรงกับเครื่องจาก FNIRSI
หรือหลักฐานใหม่ที่ตรวจสอบกฎการยอมรับไฟล์ได้ ไม่ใช่คัดลอก PN 1.13 ซ้ำ
