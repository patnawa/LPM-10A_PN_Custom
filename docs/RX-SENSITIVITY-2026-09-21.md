# RX: ปุ่ม sensitivity, เกนฮาร์ดแวร์ และเสียงบอกความแรง (PN 1.14 → 1.15, 2026-09-21)

หลังติดตั้ง PN 1.14 (เสียง Analog ต่ำกว่า Digital 1 octave + chirp ตอนกดปุ่ม) เจ้าของเครื่อง
รายงานว่า "เสียงต่างกันชัด แต่เหมือนต้องเร่งปุ่มจนเกือบสุดทั้งสองโหมดถึงหาสัญญาณเจอ"
จึงอ่าน RAM ของตัวตรวจจับผ่าน ST-Link (อ่านอย่างเดียว, ~30 ครั้ง/วินาที: `0x20000040–0x2000011F`)
ขณะเจ้าของหมุนปุ่มไป-กลับ 3 รอบที่ตำแหน่ง probe คงที่ ทั้งโหมด Digital และ Analog
เครื่องมือ: `docs/experiments/rx_sens_capture.py`; ข้อมูลดิบใน `Desktop/LPM-10RX-SWD-2026-09-21/sens-*.jsonl`

## ผลวัด (PN 1.14, ตำแหน่งเดียว)

ปุ่ม (PA2) ถูกอ่านทุก 500 ms เป็น raw 0–4095 → gain code = raw/580 (0–7) → 3 บิตไป PB12–14
เลือกเกนของภาคขยาย และเปิด/ปิดตัววิเคราะห์ (Digital ต้อง raw ≥ 2, Analog ต้อง code ≥ 1)

| code | ช่วงปุ่ม | Digital: p-p ADC | จับได้ | duty เสียง | Analog: p-p | จับได้ | duty |
|---|---|---|---|---|---|---|---|
| 0 | 0–14 % | ~95 | 34 % | 7 % | ~460 | 0 % (gate ปิด) | 0 % |
| 1 | 15–28 % | ~230 | 92 % | 23 % | ~420 | 98 % | 27 % |
| 2 | 29–42 % | ~780 | 100 % | 27 % | ~1020 | 98 % | 34 % |
| 3 | 43–56 % | **~90** | 100 % | 20 % | **~200** | 90 % | 17 % |
| 4 | 57–70 % | ~1920 | 100 % | 40 % | ~1840 | 100 % | 42 % |
| 5 | 71–85 % | ~1940 | 100 % | 36 % | ~1850 | 100 % | 41 % |
| 6 | 86–98 % | ~2040 | 100 % | 41 % | ~1940 | 100 % | 42 % |
| 7 | 99–100 % | ~2400 | 100 % | 42 % | ~2020 | 94 % | 29 % |

ข้อค้นพบ:
1. **ตัวตรวจจับไม่ได้ไวน้อยกว่าโรงงาน** — ล็อกสัญญาณตั้งแต่ code 1 (ปุ่ม ~15 %) ทั้งสองโหมด
2. **เกนฮาร์ดแวร์มีจริง 3 ระดับ**: code 0 และ 3 ต่ำสุด (code 3 ตกหลุม — ตรงกับที่ RX-AUDIT ตั้งข้อสังเกตว่า
   เฟิร์มแวร์เขียน pin pattern ของ 0 เท่ากับ 3), code 1–2 กลาง, code 4–7 สูงและแทบเท่ากัน (ต่างกัน ~1.1×)
3. คะแนนความแรงของ PN 1.8–1.14 คือคอนทราสต์ ADC ตรง ๆ ซึ่งขึ้นกับเกน ~20× → **หมุนปุ่มขึ้น = จังหวะเร็วขึ้น**
   ทั้งที่สายอยู่ที่เดิม จึงรู้สึกว่า "ต้องเร่งปุ่มถึงเจอ" (โรงงานบี๊บ 50/50 ms คงที่ทันทีที่จับได้)
4. Analog ที่ code 7 กับสัญญาณแรง (p-p > 2500, ชนเพดาน ADC ด้านบน) หลุดล็อกเป็นช่วง — เป็น clipping
   ที่โรงงานก็เป็น ทางแก้คือลดปุ่ม

คอนทราสต์มัธยฐานต่อ code (Digital, ตำแหน่งเดิม): 1692 / 3712 / 13009 / 1708 / 31982 / 30547 / 32179 / 34060
→ ตัวคูณเทียบ code 7: 20 / 9.2 / 2.6 / 20 / 1.07 / 1.11 / 1.06 / 1

## PN 1.15 `rx-gain-norm`

Digital และ Analog ส่งคะแนนผ่านฟังก์ชันโค้งเดียวกัน (`0x0800A048`) จึงแทรก helper ต่อท้าย image:
คะแนน × ตัวคูณข้างต้น (หน่วย 1/10: 200/92/26/200/11/11/11/10) แล้วค่อยเข้าโค้ง และแก้ปลายโค้ง
gap จาก 160/130/105/75/45/20 → **110/95/85/70/45/20 ms** (สัญญาณอ่อนสุดยังได้ยิน ~7 พัลส์/วิ)
ไม่แตะตัวตรวจจับ/การปล่อย/upper-rail; ไม่ใช้ RAM เพิ่ม; `rx-sdk/gain_norm.py`, `test_rx_gain_norm.py` (7 เทสบน unicorn)

### ยืนยันบนเครื่อง (PN 1.15, Digital, หมุนปุ่มที่ตำแหน่งเดิม)

| วินาที | ปุ่ม | code | gap ที่ publish (ms) |
|---|---|---|---|
| 1 | 1627 | 2 | 40 |
| 2 | 2838 | 4 | 40 |
| 3 | 3796 | 6 | 39 |
| 4 | 3236 | 5 | 40 |
| 9 | 1125 | 1 | 41 |
| 11 | 2982 | 5 | 43 |
| 13–14 | 4094 | 7 | 41 |

จังหวะคงที่ ~40 ms ทุกตำแหน่งปุ่มตั้งแต่ code 1 (ก่อนหน้า: 130 → 70 ms ตามปุ่ม) เมื่อขยับ probe ออก/เข้า
ที่ปุ่มคงที่ gap เปลี่ยน 20–69 ms และหลุดการตรวจจับเมื่อห่างมาก — ปุ่มทำหน้าที่ตัดสัญญาณอ่อน จังหวะบอกความใกล้

## สิ่งที่ยังทำได้ต่อ

- ตัวคูณมาจากตำแหน่งเดียว/เครื่องเดียว; ถ้าเครื่องอื่นเกนต่างกัน ปรับ `MULT_X10` ใน `gain_norm.py`
- code 3 ที่ตกหลุมเกน: แก้ในเฟิร์มแวร์ได้ (map code 3 → pattern ของ code 2 หรือ 4) ถ้ายืนยัน pin pattern จากบอร์ด
- Analog clipping ที่เกนสูง: อาจให้ AGC ลดเกนอัตโนมัติเมื่อชนเพดาน (ต้องรู้ pin pattern เช่นกัน)
