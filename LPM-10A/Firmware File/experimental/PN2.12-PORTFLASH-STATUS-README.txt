Addresses the follow-up report: PN 2.11 on a D-Link gigabit switch sometimes
leaves the switch LED on for a long time instead of blinking consistently.
The GPIO-driven hold timer can be restarted indefinitely by input pulses.
That failure is reproduced in emulation; its occurrence on the board remains
unconfirmed.

PN 2.12 uses the PHY's current link-status register for acquisition and hold
decisions. It clears historical latch-low status and rejects invalid all-ones
reads. The tester indicator uses the same controller state without making
concurrent MDIO transactions. Includes all PN 2.11 features and fixes.

Use the existing TX update procedure in the root README. With the tester off,
hold M + Power, connect USB-C and copy the TX image to the update drive. Wait
for completion, power-cycle and confirm About says PN 2.12. The README covers
the vendor-filename fallback if needed. Retain the prior working TX image.

Test the same D-Link port and cable for ten minutes, unplug/replug and
exit/re-enter. Observe the switch LED and tester indicator separately.
Negotiation can still produce long off gaps: this retains 10 Mb/s advertisement,
500 ms polling and 4/8/16-second retries. RX firmware is unchanged.
